# ADR-0011 — Batas modul AI, metode retrieval awal, adapter provider, dan validasi oleh kode (Tahap 4)

- **Status:** Diusulkan · menunggu persetujuan pemilik
- **Tahap:** 4 · **RENCANA** perilaku (belum dibangun); mengikat urutan kerja berikutnya · mengikuti AGENTS.md §5 (batas modul) dan §8 (aturan AI) · tidak mengubah kontrak inti (#4 status AI, #6 pemeriksaan ulang, #7 kill switch dipakai apa adanya)
- **Asumsi dipakai:** D-10, D-15, D-20, D-21, D-22, D-23 default usulan (**ASUMSI**, Terbuka). **D-09 (provider, model, batas biaya, data yang dikirim) Terbuka tanpa default ⇒ provider berbayar TIDAK dibuat**; hanya mock.

## Konteks
Prompt Tahap 4 §8 mewajibkan metode retrieval dicatat dalam ADR; §9 dan §16 mewajibkan sumber terfilter, fakta dari Kartu Program, dan pesan pelanggan diperlakukan sebagai data tak tepercaya; §11 mendaftar sepuluh pemeriksaan sebelum balasan AI dikirim. Pipeline otomatisasi Tahap 3 (ADR-0008: titik komit satu transaksi, `preSend`, kill switch empat tingkat, job `ai_sim`) sudah membuktikan benturan AI–admin dengan AI **simulasi**.

## Keputusan
1. **Modul (AGENTS.md §5):** `ai-agents` (agent, penempatan, perakit konteks, pipeline jawab; **adapter provider di subfolder sendiri** — logika provider tidak boleh bocor ke luar), `program-cards` (CRUD + **validator tautan murni**), `knowledge` (sumber, ekstraksi, pencarian). Antarmuka hanya lewat `index.ts`. Modul `ai-agents` memakai pipeline `automation` yang ada: job `ai_reply` menggantikan `ai_sim` pada alur yang sama; **tidak ada jalur kirim baru** (semua lewat titik komit + `preSend`).
2. **Retrieval awal = PostgreSQL full-text** (`to_tsvector('indonesian', …)`, GIN pada `knowledge_source_versions.content_tsv`, sudah ada di migrasi 0008). Alasan: tanpa dependensi/biaya/data keluar, deterministik, tertelusur (hasil = baris + versi), dapat diuji dan dibatasi hak akses dengan SQL. Batas jujur: tidak semantik dan kualitas stemmer `indonesian` **belum diukur**. **Vektor/hibrida ditunda** sampai set uji (D-21) menunjukkan kebutuhan; perubahan metode = ADR baru. Awal: satuan = satu versi sumber (pemotongan/chunk ditunda; panjang konteks dibatasi kode).
3. **Filter sebelum model (CCP 4.1):** perakit konteks membentuk himpunan sumber = irisan dua arah (ADR-0010 §4) atas **versi terbit** milik agent yang **ditempatkan** di channel; kueri pencarian hanya berjalan pada himpunan itu. Isi sumber lain **tidak pernah** diambil dari DB untuk permintaan itu. ID dan versi sumber yang benar-benar masuk konteks dicatat bersama jawaban; yang ditampilkan ke internal = yang dipakai.
4. **Fakta dari Kartu Program, bukan model (CCP 4.2):** harga, jadwal, persyaratan, lokasi, dan **tautan** dirender **kode** dari versi terbit kartu. Model tidak menghasilkan URL; tautan disisipkan kode **hanya** setelah `evaluateProgramLink(kartu, sekarang)` (aktif · belum lewat tutup pendaftaran · jadwal belum lewat · URL ada; zona Asia/Jakarta) lolos. Gagal ⇒ tanpa tautan, "akan dikonfirmasi", eskalasi. Harga/diskon/cicilan di luar kartu ⇒ eskalasi.
5. **Adapter provider:** antarmuka tunggal (`complete(konteks) → teks + pemakaian`), **`MockProvider` bawaan** tanpa jaringan untuk semua tes. **Tidak ada provider nyata sebelum D-09 Diputuskan** dan sebelum Gate 3 untuk pengiriman nyata. Kredensial per lingkungan lewat env (tidak pernah masuk log/UI/simulator); data dikirim seminimal mungkin (tanpa nomor telepon/identitas); provider, model, versi konfigurasi, versi sumber, dan pemakaian dicatat (tabel baru, expand-only, **setelah** D-09). Batas biaya diperiksa **sebelum** panggilan dan gagal-tertutup.
6. **Sepuluh pemeriksaan (prompt §11):** diperluas dari titik komit Tahap 3 (kill switch → AI Aktif → versi sama → kelayakan pesan → jendela layanan → penerima uji) dengan: channel/agent aktif, agent masih agent yang ditetapkan, validasi jawaban (gaya, tautan, media), dan batas biaya. Gagal satu ⇒ tidak kirim, alasan tercatat, tandai admin. Pemrosesan **berurutan per percakapan**; hasil agent lama tidak dikirim setelah pergantian/ambil alih (pemeriksaan ulang versi + penempatan).
7. **Eskalasi:** aturan alasan → tim ada di `config` versi agent; default D-20/D-22/D-23 (ASUMSI). Efek: tandai "butuh admin" + AI Off (`ai_off_reason` `eskalasi` sudah ada di mesin status) + alasan/waktu/versi agent tercatat + notifikasi **dalam TE One** (bentuk notifikasi diputuskan saat implementasi; tabel belum ada). Pesan pengantar hanya terkirim bila lolos pemeriksaan ulang dan admin belum mengambil alih; **tanpa janji waktu** (D-15).
8. **Simulator & set uji terisolasi (CCP 4.7):** memanggil perakit konteks + validator + `MockProvider`/provider, **tanpa** menulis percakapan, pesan, outbox, label, pipeline, atau follow-up dan **tanpa** jalur kirim (dijaga uji statis impor + uji perilaku). Hasil batch disimpan per versi agent (tabel baru, expand-only) untuk membandingkan regresi kualitas.
9. **Keamanan AI:** pesan pelanggan dan isi dokumen = data tak tepercaya, ditempatkan terpisah dari instruksi sistem dan tidak dapat mengubah sumber/hak/aturan; keluaran divalidasi aplikasi sebelum kirim; tidak ada alat/aksi bebas bagi model. Kasus injeksi (minta rahasia, baca knowledge agent lain, abaikan eskalasi, tautan/harga palsu) menjadi bagian set uji.
10. **Urutan kerja (tiap langkah = PR kecil + tes + mutasi):** (1) **struktur** (ADR-0010, migrasi 0007–0008, izin) — *PR ini*; (2) Kartu Program + validator tautan; (3) knowledge + ekstraksi + FTS; (4) agent CRUD/versi/terbit/penempatan + pergantian; (5) pipeline jawab dengan `MockProvider` + sepuluh pemeriksaan + eskalasi; (6) simulator + set uji + ambang D-21; (7) provider nyata **setelah D-09**; (8) uji nyata **setelah Gate 3**.

## Konsekuensi
- (+) Tidak ada jalur kirim baru dan tidak ada provider berbayar sebelum keputusan pemilik; seluruh tes Tahap 4 berjalan tanpa jaringan.
- (+) Fakta bisnis tidak pernah berasal dari teks bebas model: risiko fabrikasi harga/tautan ditekan secara struktural.
- (−) FTS tidak menangkap sinonim/semantik; jawaban dari knowledge bisa luput pada pertanyaan berparafrase — diukur oleh set uji sebelum memutuskan vektor.
- (−) Definisi "jadwal belum lewat" masih ASUMSI (ADR-0010 §5).
- **Alternatif ditolak:** vektor sejak awal (dependensi, biaya, data keluar, belum ada bukti perlu); membiarkan model menulis tautan lalu memvalidasi (celah injeksi); jalur kirim khusus AI di luar pipeline Tahap 3 (melemahkan kontrak #6/#7).
